## Problem Statement
지급 요청을 승인할 때 앞으로 예정된 지급계획을 몰라, 요청 금액이 작으면 승인해 왔다. 현재의 승인이 다음 자금계획에 영향을 줘 자금 부족이 생기는 것이 가장 큰 걱정이다.

## Demand Evidence
- 사용자 본인 발언: "앞으로 예정된 지급계획을 몰라서 지급 요청건 금액의 크기만 보고 금액이 작으면 수락했다."
- 사용자 = 승인자 = 프로그램 실행자(같은 사람). 매주 실제로 쓰는 업무.

## Status Quo
- 지급 요청은 인트라넷(intranet.plant8.co.kr) 결재와 메일로 들어옴.
- 일주일 내내 요청을 보며 자금계획에 반영하고, 목요일 14시까지 그 주 금요일 지급분을 일괄 승인 → 금요일 지급.
- 판단 근거는 요청 건의 금액 크기뿐. 예정 지급·입금 일정은 한 화면에 없음.

## Target User & Narrowest Wedge
- 사용자: 지급 승인권자(이 대화의 사용자 본인).
- 가장 작은 쓸모: 요청이 들어올 때마다 더블클릭 한 번으로 "이 요청들을 승인하면 앞으로 8주 잔액이 언제 얼마까지 내려가나"를 보는 화면.

## Constraints
- Python 3.8+ 표준 라이브러리만, Windows 외장하드(F:)에서 실행. 기존 결정 D-01~D-15 유지(미확인은 0 아님 등).
- 인트라넷: 엑셀 내려받기 없음, DB 직접 접근 어려움 → 로그인 후 화면 수집(읽기 전용). 비밀번호는 실행 시 본인 입력, 채팅·저장소에 남기지 않음.
- WEHAGO: 사용자가 직접 엑셀을 받음. 매출원가는 연말 결산 때만 장부에 반영되므로, 월중 원가는 분개장 6xxxx "(도)" 도급원가 계정의 월별 합으로 계산.

## Premises (사용자 확인)
1. 프로그램은 요청이 들어올 때마다 언제든 돌리는 도구다(목요일은 승인 버튼만 누르는 날). — 사용자 정정 반영
2. 첫 화면 질문: "대기 중인 요청을 승인하면, 이미 잡힌 지급·들어올 돈까지 넣었을 때 잔액이 언제 얼마까지 내려가나?" 요청별로 "이 건을 빼면 최저 잔액" 표시.
3. 진짜 빈칸은 앞으로의 지급계획 데이터다. 미등록 금액은 "미등록"으로 드러낸다.
4. 승인 판단에는 WEHAGO가 필요 없다(은행 잔액 + 인트라넷). WEHAGO는 월간 손익 전용.
5. 7개 묶음 보고서는 월간 보고서·상세자료로 유지하고, 주간은 승인 화면이 맨 앞.

## Approaches Considered
- A. 지금 프로그램 + 체크 화면 — 채택.
- B. 새 ERP 결재 화면에 넣기 — ERP 개발 일정에 묶여 몇 주 이상 걸려 제외(계산 엔진은 나중에 재사용 가능).
- C. 엑셀 자금계획표 — 손댄 값과 원자료가 섞일 위험으로 제외.

## Recommended Approach (A)
1. 수집기(`수집_인트라넷.py`, 로컬 실행): 로그인 → 지급요청·프로젝트·지급계획 화면 읽기 → 입력 CSV. 쓰기·승인 동작 없음.
2. 계산: 기존 `calc.compute` 재사용. 대기 요청을 "승인 대기"로 표시해 일정에 포함/제외 두 경우 계산.
3. 화면: HTML 맨 위에 승인 대기 목록(체크박스). 체크를 켜고 끄면 8주 주별 잔액·최저점이 즉시 다시 계산됨(내장 JS, 외부 라이브러리 없음). 요청별 "제외 시 최저 잔액" 열.
4. 실행: `실행_승인검토.bat` 더블클릭 → 비밀번호 → 화면.

## Success Criteria
- 새 요청이 온 뒤 5분 안에 "전부 승인 시 최저 잔액과 날짜"를 볼 수 있다.
- 체크 하나를 바꾸면 1초 안에 최저 잔액이 다시 계산된다.
- 날짜·금액 미확인 건은 0으로 합산되지 않고 건수로 보인다.
- 목요일 승인 전에 "부족 발생 주"가 있으면 첫 줄에 보인다.

## 인트라넷 화면 구조 (2026-11-02 읽기 전용 확인)
- `/payment/index`: 지급요청 목록. 열 = 번호, 행사명([프로젝트번호] 포함), 파트너, 등록일, 행사일, 금액, 지급요청일, 등록자, 팀장승인, 관리팀승인, 사장님승인. 검색 폼: gyear, team, subteam, project, partner, writer, search, confirm(팀장/관리팀/대표이사 미승인). 페이지 나눔 있음(10페이지 이상).
- `/project/index`: 프로젝트 목록. 열 = 클라이언트, 담당자, PO번호, 행사일, 행사명, 국, 팀, 계산서, 사전견적, 견적금액, 실행가, 수익률, 승인 4단계.
- `/project/payment?pro_num=N`: 프로젝트별 예산 행(대분류·소분류·단가·수량·일·최종견적가·최종실행가·매출이익·업체명) + 페이먼트.
- **안전 규칙:** 승인·삭제가 GET 링크(`/confirm/...`)로 되어 있음. 수집기는 위 3개 경로만 허용 목록으로 읽고, `/confirm`·`/logout`·삭제 경로는 절대 요청하지 않는다(코드로 차단 + 테스트).
- "대표이사 미승인" 필터 = 승인 대기 목록. 프로젝트 최종실행가 − 요청된 지급 = 아직 요청 안 된 지급(날짜 없음 → 미등록 일정으로 표시).
