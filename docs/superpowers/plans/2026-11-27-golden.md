# 1단계: 정답 예시(골든) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (규칙 묶음 작업) — 체크박스(`- [ ]`)로 진행을 적는다.

**Goal:** 지금 파이썬 프로그램이 내는 숫자를 "가상 자료 → 기대 숫자" JSON으로 남겨, 새 타입스크립트 시스템이 1원까지 같은지 자동으로 비교할 기준을 만든다.

**Architecture:** 사례(case)마다 입력 폴더(입력/·수집/·수집/위하고/)를 만드는 파이썬 빌더가 있고, 추출기가 지금 프로그램(convert.run → data.load → calc.compute)을 돌려 기대값을 JSON으로 쓴다. 검사기는 다시 돌려 기대값과 비교한다. 입력과 기대값은 모두 저장소에 둔다(새 시스템 시험이 그대로 읽음).

**Tech Stack:** Python 3 표준 라이브러리, 기존 tests/ 가상 자료 도구(write_fake_books, auto_json, write_fake_snapshot, write_sales, make_sample).

**Spec:** 개발 계획 https://claude.ai/artifact/B9415mJgnLuPGuCKD1dGuM (1단계), 단순화 검토 1절 '결과가 맞다고 보는 규칙'.

## Global Constraints
- 실제 회사 자료 0줄. 모든 입력은 가상. 주민번호 모양 문자열 금지(검사기가 확인).
- 기대값에 임시 폴더 경로·현재 시각이 들어가지 않게 바꿔 쓴다(`<TMP>`).
- 기대값 JSON: UTF-8, 키 정렬, 들여쓰기 1, 날짜는 `YYYY-MM-DD`, 튜플·집합은 목록.
- 지금 프로그램 코드는 바꾸지 않는다(읽기만).
- 지금 프로그램이 틀렸다고 보이는 숫자는 기대값으로 삼되 `RULES.md`의 '의심' 칸에 적어 사용자에게 보고.

## Review Focus

- 받다 만 자료(분개장 JSON 줄수 불일치) → 거부되어 '미확인'으로 남는지 사례로 고정.
- 같은 금액·같은 날 두 거래처 → 거래처코드가 다르면 다른 지급.
- 자료 문턱: 자금계획서 없음·8일 묵음 → 대표 보고 만들지 않음(gate) 사례.
- 설정 값이 틀림/비어 있음 → 기본값과 입력 확인 목록.

## 파일 구조
- `golden/README.md` — 사례 폴더 모양, 새 시스템이 읽는 법
- `golden/RULES.md` — 규칙 표(번호, 규칙, 사례, 기대값 위치, 의심)
- `golden/cases/<id>/case.json` — {id, title, rules[], asof, kinds[], payday?}
- `golden/cases/<id>/input/{입력,수집,수집/위하고}/…` — 가상 입력
- `golden/cases/<id>/expected/{convert,weekly,monthly,gate}.json`
- `tools/golden/build.py` — 사례 입력 만들기(사례마다 함수 하나)
- `tools/golden/extract.py` — `extract(case_dir) -> dict`, `write(case_dir)`, `check(case_dir) -> list[str]`(차이)
- `tests/test_golden.py` — 모든 사례 `check` 가 빈 목록
