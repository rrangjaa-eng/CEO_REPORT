# 2단계: 연결부터 실제로 만들기 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. 체크박스로 진행을 적는다.

**Goal:** 본인만 들어가는 Cloud Run 사이트, 그 사이트에만 자료를 넘기는 수집 확장 1.0, 기본 가지에 합치면 자동 배포를 실제 코드로 만든다(시험 제작 아님).

**Architecture:** web/(Vite+TS, 브라우저 안에서만 자료 보관·계산) → server/(Node 내장 http, 정적 파일 + 보안 머리글 + IAP 확인) → Docker → Cloud Run(us-central1, IAP). extension/(TS+esbuild, MV3)이 위하고 조회 응답을 모아 chrome.storage에 두고, externally_connectable 로 내 사이트에만 준다.

**Tech Stack:** TypeScript 5.9.3, Vite 7.3.8, Vitest 3.2.7, fake-indexeddb 6.2.8, esbuild 0.28.2, @types/chrome 0.3.8, Node 22, GitHub Actions(google-github-actions/auth@v2, setup-gcloud@v2).

### Task 1: 사이트 자료 다루기 (web/src/collect)
- docs.ts: `checkDoc(raw: unknown): {ok: true, doc: CollectedDoc} | {ok: false, reason: string}` — 종류·형식·줄수==줄.length·열 확인. `docKey(doc): string` = 종류|기간|회사
- store.ts: IndexedDB 'ceo-report' v1, store 'docs'. `saveDocs(docs)`, `listDocs()`, `clearAll()`, `exportBackup(): Promise<Blob>`, `importBackup(file: Blob): Promise<number>`
- extension.ts: `fetchFromExtension(extId: string): Promise<unknown[]>` (chrome.runtime.sendMessage, 확장 없으면 알기 쉬운 오류)
- 시험: 받다 만 자료 거부, 백업 왕복 같음, 같은 key 는 새 것으로 덮음

### Task 2: 화면 (web/src/main.ts)
- 로그인한 이메일(/api/me), [확장에서 받기], 받은 자료 목록(종류·회사·수집시각·줄 수), [백업 내보내기]/[백업 불러오기]. 계산은 3단계

### Task 3: 서버 (server/)
- iap.mjs: `verifyIapJwt(token, now, keys): {email} | null` ES256, iss https://cloud.google.com/iap, exp/iat 확인. 키는 https://www.gstatic.com/iap/verify/public_key-jwk 에서 받아 1시간 보관
- server.mjs: IAP 확인 → ALLOWED_EMAIL 비교 → 정적 파일. /api/me → {email}. 보안 머리글
- 시험(node --test): 서명 없음 403, 다른 이메일 403, 맞는 이메일 200, index no-store, assets immutable, CSP 머리글

### Task 4: 수집 확장 1.0 (extension/) — 에이전트
- chrome_extension 의 수집 동작을 TS로 옮김(위하고 화면 다루는 방식은 그대로). 받은 자료를 chrome.storage.local 에도 둠. onMessageExternal: sender.origin 이 사이트 주소일 때만 {type:"list"} 에 자료 목록으로 답함. 파일 저장은 비상용으로 남김
- 시험: 다른 origin 거절, list 응답 모양
