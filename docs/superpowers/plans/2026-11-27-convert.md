# 자료 변환을 타입스크립트로 옮기기 (2026-11-27)

파이썬 `ceo_report/convert.py` 의 "자료 변환" 단계를 `web/src/convert/` 로 옮겼다. 함수는 파일을 읽거나 쓰지 않는다.
입력은 `'입력/…'`, `'수집/…'` 상대 경로를 바이트에 잇는 묶음이고, 결과는 쓸 CSV 글·종료 코드·화면 줄이다.

```ts
convert(input: ConvFiles, asof: IsoDate, now: "YYYY-MM-DD HH:MM:SS", opts?: ConvertOpts)
  : Promise<{ code: number; lines: string[]; files: Record<string, string> }>
```

- `files`: 입력 폴더 안 파일 이름에 그 파일에 쓸 글을 잇는다. 글은 UTF-8 BOM으로 시작하고, `csv.writer` 와 같은 모양에 줄 끝은 `\r\n` 이다. 이번에 만든 범위 안 CSV 전부와, 자금일정 정리로 바뀐 `자금일정.csv`·`자금일정_지난기록.csv` 가 들어간다.
- `opts`:
  - `skipPartialJournal`: D7. 기본은 켜짐이다.
  - `mtimes`: 파일 수정 시각(초). 같은 날짜 자료를 고를 때만 쓴다.
  - `fileDays`: 기존 계산서.csv 의 작성일. 알림에만 쓴다.
  - `stamp`: 이전 파일 폴더 이름.

## 결과

- **golden 46개 사례**(`web/tests/convert/golden.test.ts`)는 모두 기대값과 같다. 다음 네 가지를 본다.
  - 종료 코드
  - 범위 안 CSV 를 글자까지. 기대에 없는 범위 안 CSV 는 입력 파일과 바이트가 같아야 한다(바뀌지 않음).
  - 화면 줄을 순서까지. 아래 빼기 목록에 든 줄만 뺀다.
  - 범위 안 대조 불일치·판단 불가 건수가 기대 건수 이하인지
- **D7**(`d_partial_journal`)은 `web/tests/convert/known_changes.ts` 에 적었다.
  - 옛 규칙(`skipPartialJournal: false`)으로 돌리면 기대값과 정확히 같다.
  - 새 규칙으로 돌리면 받다 만 `261101 분개장 자동수집.json` 을 뺀 변환과 파일·줄이 같다. 다른 점은 경고 한 줄이 더해지고 코드가 0 이라는 것뿐이다.
  - `f_tax_missing` 은 분개장이 받다 만 파일 하나뿐이라 새 규칙에서도 코드 3 으로 기대값과 같다.
- **끝까지 시험**(`web/tests/convert/e2e.test.ts`):
  - 입력 폴더를 TS 변환 결과로 덮는다. 범위 밖 파일은 기대값을 그대로 둔다.
  - 그 폴더로 `loadData` + `buildReport` 를 돌려 R 과 stop 을 calc golden 과 같은 방식으로 비교한다. calc 의 `KNOWN_CHANGES` 를 그대로 쓴다.
  - 46개 사례가 모두 같다. 명령이 시작 전에 거부한 사례 하나(R 없음)는 건너뛴다.
- **검사**: 아래가 모두 통과한다. convert 시험은 `TZ=UTC` 로도 통과한다.
  - `TZ=Asia/Seoul npm run check`

## 화면 줄 빼기 목록

기대값과 결과 양쪽에서 같이 뺀다. 무늬와 까닭은 `web/tests/convert/golden.ts` 의 `EXCLUDED_LINES` 에 있다.

| 무늬 | 까닭 |
|---|---|
| `^(위하고대조\|연간자료\|현금흐름\|계정잔액\|사원\|급여명세\|연말정산\|고정자산\|잉여금\|세무조정\|신고일정\|신고도우미\|자료대조\|차입금\|카드사용)\.csv 만듦 N줄` | 범위 밖 표를 만든 줄 |
| `^\[(같은 이름들)\.csv\] 만들지 않음 — ` | 범위 밖 표를 만들지 않은 줄 |
| `^대조 (불일치\|판단 불가) N건$` | 건수에 범위 밖 표의 대조와 위하고대조 쪽 파일 사이 대조가 섞인다. 대신 범위 안 건수가 기대 건수 이하인지 따로 본다. |
| `^홈택스 ` | 홈택스 전자세금계산서 대조(`hometax.compare`)는 범위 밖 |
| `^거래처 계좌 목록` | 이체용 거래처 등록(`transfer.register_vendors`)은 범위 밖 |
| `^(지급 요청서\|최근 인트라넷 수집에 지급 요청서\|경고: 최근 수집의 지급 요청서)` | 지급요청서.csv 옮기기(`payreq.write`)는 옮기지 않음 |
| `^경고: (자동분석\|확인할것)\.json` | 자동분석·확인할것 저장은 범위 밖 |

비교 전에 줄 두 가지를 고친다. 빼는 것은 아니다.
- `대조 내용: <임시 폴더>/입력/변환결과.txt` 는 `입력/변환결과.txt` 로 바꾼다.
- `이전 파일: … (목록)` 에서는 범위 밖 표 이름을 뺀다.

46개 사례에서 실제로 빠지는 줄은 앞의 세 무늬뿐이다. 홈택스·거래처 계좌·지급 요청서 줄은 golden 에 없다.

## 알려진 한계

- **수정 시각**: 브라우저 묶음에는 파일 수정 시각이 없다. `opts.mtimes`(없으면 0)로 받는다.
  - 파이썬은 같은 날짜 이름의 장부·자금계획서를 수정 시각으로 고른다. 시각을 주지 않으면 이름 순으로만 고른다.
  - 기존 계산서.csv 를 그대로 둘 때 알리는 작성일은 `opts.fileDays` 로 받는다. 없으면 '알 수 없음'이다.
- **JSON 숫자**: `JSON.parse` 는 `1.0` 과 `1` 을 가르지 못한다. 그래서 정수 값의 실수(예: `1234.0`)는 파이썬 `str()` 의 `"1234.0"` 과 달리 `"1234"` 가 된다(`pyjson.ts`). 확장이 쓰는 자동수집 파일에는 그런 값이 없다.
- **오류 글**: 깨진 JSON 에 대한 파이썬 예외 글(위치·까닭)은 똑같이 만들 수 없다. 읽지 못했다는 판단과 앞부분 글은 같다.
- **옮기지 않은 것**:
  - 변환결과.txt 와 그 안의 연결 목록
  - 확인할것.json·자동분석.json(`checklist`·`insights`)
  - 지급요청서.csv 옮기기(`payreq`)
  - 홈택스 대조
  - 거래처 계좌 등록(`transfer`)
  - 잠금 파일
  - 쓰기·되돌리기·이전 폴더 복사. 호출한 쪽이 `files` 를 쓴다.
  - 범위 밖 표 전부와 위하고대조 쪽 파일 사이 대조 3개
- **화면 줄**:
  - '대조 불일치/판단 불가' 건수는 범위 안 표의 대조만 센다. 그래서 파이썬보다 작거나 같다.
  - '이전 파일' 목록에는 범위 안 표와 변환결과.txt 만 나온다.
  - 범위 밖 표가 내는 `[확인]` 알림은 나오지 않는다. golden 에는 그런 알림이 없다.
- **입력 확인 건수**(`보고서 입력 확인 필요 N건`): 이번에 만든 범위 안 CSV 를 덮은 입력 폴더로 `loadData` 를 돌려 센다. 파이썬은 범위 밖 CSV 까지 쓴 뒤에 센다. golden 46개 사례에서는 건수가 같다.
- **오늘 날짜**: 파이썬 `dt.date.today()`(자금일정 정리일, 세금 판단)는 `now` 의 날짜를 쓴다.
- **D7 경고 자리**: 경고 줄은 'WEHAGO 장부 기준일' 줄 바로 뒤에 둔다. 버린 파일은 쓰지 않은 파일 목록(`books.unused`)에 들어간다.
