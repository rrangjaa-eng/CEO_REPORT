## Planner decisions (wiring)

- W-1 run order: config → books (not ok → exit 3, unchanged) → snapshot → requests / projects → links → match =
  wehago.match_requests(books, requests) (only with a snapshot) → read_prev for every generated CSV (before anything is
  backed up) → sales = wehago.load_sales(wehago_dir, asof, books) → Tables: 손익 (build_pl), 계산서 (build_invoices),
  and with a snapshot 프로젝트 (build_projects), 프로젝트집행 (build_execs), 위하고대조 (build_xchk with the 프로젝트 Table
  rows and meta from the run) → cross-file Checks → step A: one all-or-nothing write of the CSV Tables (02-01 path) →
  data.load listing on the replaced folder (W-6) → step B: 변환결과.txt through the same safe path. A failure in step A
  replaces nothing (exit 7); a failure in step B keeps the new CSVs, prints the error and exits 7.
- W-2 no snapshot: 프로젝트 / 프로젝트집행 / 위하고대조 are Table(written=False, reason '인트라넷 스냅숏 없음 (기존 파일
  그대로)') and the write path neither backs them up nor touches them. Reason: those files need the intranet list (D-42);
  the previous ones stay usable for the report until the next snapshot.
- W-3 no usable sales file (state ≠ 'ok'): when 입력/계산서.csv exists it is included in the backup and removed in the
  same all-or-nothing step (D-41: the report must show '자료 없음', and D-43: existing files are moved to 이전 first).
- W-4 cross-file Checks (section '[파일 사이 대조]', counted in '대조 불일치'): the csv side of 손익's 직접비 Check vs
  the csv side of 프로젝트집행's '원가 줄 합계' Check vs 위하고대조 'WEHAGO 원가' + 미연결원가 rows; 손익 매출 vs 위하고대조
  매출계약 'WEHAGO 매출' + 매출미연결; Σ 손익 '프로젝트 미연결' 직접비 vs 위하고대조 미연결원가 vs Σ 공급가액 of 프로젝트집행
  WEHAGO rows (근거 starting 'WEHAGO') whose 프로젝트번호 is not a 프로젝트.csv key. Card rows' 공급가액 include VAT, so the
  third sums `extra['cost_portions']` of those rows (provided by build_execs, plan 02-04 interface), never 공급가액. Only the Checks whose files were both
  written run.
- W-5 자금일정 overlap: read 입력/자금일정.csv with util.read_csv (data.SCHEMA columns) read-only; never modify it; list
  pairs per the truth; count line always printed (0 included).
- W-6 data.load listing: after the CSV replace, `data.load(input_dir)` and list its issues as '  확인 <file> <line>번째 줄:
  <message>' (masked), count line '보고서 입력 확인 필요 N건'. Manual files that still use other project numbers (the
  sample uses 'P26201'; generated files use the intranet key '26201') appear here, which is the intended signal.
