## Interface contract

- `build_projects(projects, revenue, prev_rows)` — projects: linking.projects_of result; revenue: linking.link_revenue
  result; prev_rows: convert.read_prev(input_dir, "프로젝트.csv"). Returns Table('프로젝트.csv',
  data.SCHEMA['프로젝트.csv'] + ['실행가'], rows, checks, notes).
- `build_execs(books, costs, requests, match, prev_rows, cfg)` — costs: linking.link_costs result; requests:
  linking.requests_of; match: wehago.match_requests(books, requests); prev_rows: read_prev(..., "프로젝트집행.csv");
  cfg: convert.read_config. Returns Table('프로젝트집행.csv', data.SCHEMA['프로젝트집행.csv'], rows, checks, notes) with
  `extra['cost_portions']` = list aligned with rows (cost part of each WEHAGO row — differs from 공급가액 only on card rows,
  which carry 총액 — and None for request, diff and carried rows); plan 02-07 uses it for a cross-file check.
- Both are deterministic and independent of input order.

## Planner decisions (D-42 details)

- E-0 프로젝트.csv columns (D-49): 프로젝트번호 = key; 프로젝트명 = name; 팀; 클라이언트; 사전견적예산 = cell_amount(estimate);
  매출반영누계 = Σ amounts of revenue lines linked to the key (all dates in the 분개장; '' if any is unknown; 0 when none);
  행사일 = intranet text; 실행가 = cell_amount(budget). 상태, 예산수정일, 계약금액, 완료일 are not in the intranet list or
  WEHAGO (D-49: never filled from 매출): carried from the previous 프로젝트.csv row whose 프로젝트번호 has the same digits (exactly one such row; blank when there is none;
  amounts normalised with util.num → cell_amount; several → not carried, note). Duplicate snapshot keys: first row only,
  note '프로젝트번호 <key> 겹침 → 첫 줄만'.
- E-1 cost groups: cost lines grouped by (전표일자, 전표번호, vendor_norm, project-or-code). One row per group.
  공급가액 = Σ line amounts ('' if any unknown). VAT = Σ 차변 of vat_codes lines in the same 전표 with the same
  vendor_norm, put on that 전표+vendor's group with the largest 공급가액 (ties: first line), 0 on the others; 0 when
  the 전표 has no such line. 프로젝트번호 = linked key, else the line's own [code], else ''. 항목 = first line's 적요
  (계정과목 when blank); 거래처 = first line's vendor text.
- E-2 payment of a 전표: cash when a line with account_code in cash_codes has 대변 > 0; else payable when a line with
  account_code in payable_codes has 대변 > 0 (its vendor_norm is the payable vendor; prefer the line with the group's
  vendor_norm, else the largest credit); else unknown → 요청미지급 with 근거 suffix ' · 지급 여부 확인 불가 (현금·미지급 대변 없음)'.
  Card: the payable line's vendor text contains any cfg card_words → 카드결제완료 / 카드사용미결제, 공급가액 = 공급가 + VAT,
  부가세 '' (PROJ-02 총액).
- E-3 settlement per payable vendor_norm over payable_codes lines: items = payable credits (any date), led by an opening
  item when the vendor has lines whose 적요 contains 전기이월 or 기초잔액 (net credit−debit > 0); payments = payable
  debits dated on or before books.book_date. Pass 1: each item in date order takes the first unused payment of the same
  amount dated on or after it. Pass 2 (only when the 분개장 has at least one opening line on payable accounts): remaining
  payments in date order settle remaining items oldest first (item date ≤ payment date). Fully settled → 지급완료,
  일자 = the payment that completed it, 근거 ' · 지급 <date> 전표 <no>'; partly → unpaid with ' · 일부 지급 <won>';
  leftover payments → note '미배분 지급 N건 <won>'.
- E-4 requests (D-42 "같은 지출이 두 번 들어가지 않게"): only status 'approved' or 'pending' (others → note). By match status:
  '이미 지급' → no row. '계산서 있음' / '금액 차이' → find groups with the request's vendor_norm, project/code equal to the
  request code and group total (공급가 + VAT of that vendor in the 전표) equal to the match invoice_total: exactly one and
  unpaid → annotate it (일자 = request date, 확정여부 approved→'확정' pending→'추정', 근거 + ' · 지급요청 <번호>'); exactly one
  and already 지급완료 → no row + note; none or several → add the request row with note '지급요청 <번호>: 계산서 있음이나
  원가 줄을 하나로 정하지 못함 → 요청으로 넣음 (중복 가능)'. D-50 (D-30b in both directions): for a '금액 차이' or
  '계산서 있음' request, the rows naming it (annotated WEHAGO row and/or request row; 공급가액 + 부가세) must sum to
  max(invoice_total, amount); when they sum to less, add one diff row (상태 요청미지급, 부가세 '', same 일자/확정여부) for the
  positive difference — invoice below request: '지급요청 <번호> 차액 (인트라넷 요청 <A> − 계산서 <I>)'; request row added
  while the invoice is above the request: '지급요청 <번호> 차액 (계산서 <I> − 인트라넷 요청 <A>)'. An unknown request amount
  gives no diff row and the note '지급요청 <번호> 금액 미확인 → 차액 판단 불가'. Any other status → request row: 프로젝트번호 = code or '', 항목 = name, 거래처 = vendor,
  상태 요청미지급, 공급가액 = cell_amount(amount), 부가세 '', 일자 = cell_date(date), 확정여부 per status, 근거
  '지급요청 <번호> (인트라넷 금액, 부가세 포함 여부 미확인)'; when the vendor has unpaid WEHAGO rows → note '중복 가능: 지급요청
  <번호> — 같은 거래처의 미지급 원가 줄 N건'.
- E-5 previous rows: 집행계획미요청 rows are carried (프로젝트번호 rewritten to the key with the same digits when exactly
  one exists); all other previous rows are dropped with one count note.
- E-6 rows order: WEHAGO rows by (date, 전표번호 as int when digits, vendor), request and diff rows by 번호, carried rows
  in previous order.
