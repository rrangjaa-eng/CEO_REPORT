## Planner decisions (D-47 details)

- A-1 Where the rule lives: linking.py stays the only implementation of D-38. wehago.project_costs gains `links=None`
  and only reshapes a link_costs result into its 01.1 output shape (wehago cannot import linking: linking imports
  wehago). The code-only path stays for links=None (01.1 unit tests and any caller without links).
- A-2 Inputs in approval.build: requests = the existing req_all (same keys as linking.requests_of); projects =
  linking.projects_of(snap); overrides = linking.read_links(input_dir)[0]; settings = convert.read_config(input_dir)[0]
  keys link_days, direct_prefixes, direct_mark, vat_codes. read_links notes and read_config notes about an unusable 변환_* value are added to
  the approval issues list (A['issues']) so a bad 프로젝트연결.csv row or setting is visible on the approval screen too;
  the '설정.csv 없음 → 변환 설정 기본값 사용' note is not added (the approval screen already reports a missing 설정.csv its
  own way, and 01.1 issue counts must not change). input_dir None → empty
  overrides and the link_costs keyword defaults.
- A-3 Keys outside the list: approval._project_cost_rows appends, after the listed projects, one row per by_code key that
  is not a listed project, name '(프로젝트 목록에 없음)', budget None, requested None (same as monthly 02-06 X-1).
- A-4 Books not 'ok' (자료 없음 / 경과 / 머리글 다름 / 읽기 실패): unchanged — no linking, panels show 판단 불가 as in 01.1.
- A-5 Equality test inputs mirror convert.run (02-03 contract): the same input folder gives read_config / read_links,
  the same snapshot gives requests_of / projects_of, and the monthly side goes through build_xchk → write_table →
  load_xchk → render (02-06). Plan 02-07 runs in the same wave; this plan does not depend on its wiring.
