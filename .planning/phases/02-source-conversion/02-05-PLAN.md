## Interface contract

- `wehago.SALES_KINDS = ("매입매출장(매출)", "전자세금계산서(매출)")`.
- `wehago._sales_kind_of(name)` → '매입매출장(매출)' when the name contains '매입매출장' and, with '매입매출장' removed,
  still contains '매출'; '전자세금계산서(매출)' when it contains '전자세금계산서' and '매출'; else None.
- `wehago._kind_of(name)`: unchanged except that a 매입매출장 name with a sales kind returns ('매입매출장', False) — so
  load_books lists it in `unused` and never chooses it as the purchase ledger.
- `wehago.read_book(path, kind, file_date=None, asof=None, keep_sales=False)`: `info["sales_rows"]` is always present
  ([] unless keep_sales and kind '매입매출장'); with keep_sales the 매출 rows are kept there with the same keys as 매입 rows
  plus `type` (매입/매출유형 text). Purchase rows and every other info key are unchanged. 전자세금계산서 rows gain
  `credit_account` (대변계정 text, masked).
- `wehago.load_sales(folder, asof, books)` → dict `{state, reason, source, file, file_date, rows, notes}`; state 'ok' |
  '자료 없음' | '머리글 다름' | '읽기 실패'. Each row: `date, no, vendor, vendor_norm, item, supply, vat, total, code, type,
  credit_account` ('' where the source has no such column). Never raises (same rule as load_books).
- `convert_invoices.build_invoices(sales, books, revenue, projects, prev_rows, cfg)` — sales: load_sales result; books:
  wehago Books (state 'ok'); revenue: linking.link_revenue result; projects: linking.projects_of (empty when no
  snapshot); prev_rows: convert.read_prev(input_dir, '계산서.csv'); cfg: convert.read_config. Returns
  Table('계산서.csv', data.SCHEMA['계산서.csv'], rows, checks, notes, written, reason). Pure: no file access.

## Planner decisions (D-41 details)

- I-0 sources (Q-1 unanswered, so all three are accepted, first available wins): (a) 매출 rows of the 매입매출장 that
  load_books chose (re-read with keep_sales=True only when books.files['매입매출장']['sales'] > 0); (b) the newest
  `*매입매출장(매출)*.xlsx` (header = 매입매출장 header, only rows with 구분 '매출' are used, other rows counted in a note);
  (c) the newest `*전자세금계산서*매출*.xlsx` (header = 전자세금계산서(매입) header — assumption to confirm at UAT).
  Newest = max (file date in name, mtime, name) like load_books. Files whose name starts with '~$' are skipped. A sales
  file older than books.book_date adds the note '매출 계산서 파일 기준일 <d> — 장부 기준일 <bd>보다 N일 이전'. A chosen
  file that fails: header → state '머리글 다름', reason '매출 계산서 엑셀 머리글 다름 — <file>: 없는 열 <a, b>'; other
  read error → '읽기 실패', reason '매출 계산서 엑셀 읽기 실패 — <file>'. No fallback to a lower source when the chosen
  one fails (the user must fix the file; a silent fallback could hide newer invoices).
- I-1 project of an invoice (D-38 order applied to invoices): (1) its own [code] (row `code`) when it is a key of
  projects, or any code when projects is empty → basis '코드'; (2) else the single revenue line in revenue['lines'] with
  the same vendor_norm, the same date and amount equal to 공급가액 whose project is not None → basis '분개장 매출 줄'
  (this inherits manual 프로젝트연결.csv links); (3) else, when projects is not empty, the single non-duplicate project
  with client_norm equal to the vendor_norm and quote equal to 공급가액 → basis '자동 (클라이언트·견적금액)'; (4) else ''
  with basis '미연결' and a reason in the listing line ('분개장 매출 줄 미연결 · 클라이언트·견적금액 후보 N건' or '분개장
  매출 줄 없음 · …').
- I-2 구분: '취소' in type → '취소'; '수정' in type or 공급가액 < 0 → '수정'; 품명 contains '선금', '선수' or '계약금' →
  '선수금'; else '발행'. Values stay inside data.INVOICE_KINDS.
- I-3 receipts (D-41 '입금 = 10800 거래처별 대변'): a receipt is a journal line with account_code in receivable_codes and
  대변−차변 > 0 whose 전표 (same date and 전표번호) has a line with account_code in cash_codes and 차변 > 0. Other
  receivable credits are counted in one note and never treated as receipts. Items per vendor_norm = invoices with a
  known 합계 > 0 (공급가액 + 부가세), by 발행일. Pass 1: receipts by (date, 전표번호) each take the first open item of the
  same vendor whose 합계 equals the receipt and whose 발행일 ≤ receipt date. Pass 2 (only when the 분개장 has at least one
  receivable-code line whose 적요 contains '전기이월' or '기초잔액'): per vendor, an opening item (net 차변−대변 of that
  vendor's opening lines, when > 0) comes first, then open items by date; remaining receipts by date settle them oldest
  first (item 발행일 ≤ receipt date). 입금액 = amount applied (full 합계 or partial), 입금일 = date of the last receipt
  applied; none applied → both ''. Leftover receipts → '미배분 수금 N건 <won>' plus one line each.
- I-4 reconciliation notes (facts, not Checks, so a real difference between two sources is shown but is not counted as a
  conversion error): '참고 매출 계산서 공급가액 <A> · 분개장 매출 <B>' (B = revenue summary total); '참고 매출채권 잔액:
  분개장 <C> · 계산서 기준 <D> (차이 <C−D>)' where C = Σ (차변 − 대변) of receivable-code lines and D = Σ 합계 − Σ 입금액 +
  remaining opening items − leftover receipts; per vendor_norm with a non-zero difference one line '매출채권 잔액 차이
  <거래처>: 분개장 <c> · 계산서 기준 <d>'. Any unknown amount makes the side '미확인'.
- I-5 previous 계산서.csv: match key (norm_vendor(거래처), util.date(발행일), util.num(공급가액)); exactly one previous
  row → carry 입금예정일 (ISO via util.date, invalid → '') and 예정일확정 (kept only when it is 'Y', 'N', '확정' or '');
  several → not carried, note. 입금일/입금액 are never carried (WEHAGO decides, D-37); a matched previous row whose
  입금액 differs adds '이전 계산서.csv와 입금 기록 다름: …'. Unmatched previous rows → one count note.
- I-6 order: rows by (발행일 or max, source order). Unknown amounts are '' (cell_amount(None)).
