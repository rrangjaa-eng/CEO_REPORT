02-05 (계산서.csv project) and 02-06 (monthly cross-check) all read its results, so a cost or revenue line is linked
the same way everywhere.

## Interface contract

- `LINK_FILE = "프로젝트연결.csv"`, `LINK_COLUMNS = ["전표일자", "전표번호", "줄", "프로젝트번호"]` (extra columns such as 비고 are allowed and ignored).
- `requests_of(snap, asof, now)`, `projects_of(snap)` — PATTERNS §3.3. `projects_of(None)` → empty OrderedDict.
- `line_keys(journal)` → list of `(date_iso_or_'', 전표번호, 줄)` aligned with journal indexes — PATTERNS §3.4.
- `read_links(input_dir)` → `(overrides, notes)`; overrides: key → 프로젝트번호 (text stripped, surrounding [ ] removed).
- `link_costs(books, requests, projects, overrides, link_days=90, direct_prefixes=("6",), direct_mark="(도)", vat_codes=("13500",))` and
  `link_revenue(books, projects, overrides, revenue_codes=("41200",))` → `{"lines", "summary", "used"}` — PATTERNS §3.4;
  `used` = set of override keys applied.
- `unused_links(books, overrides, used)` → list of `(key, project, reason)` with reason '지정한 줄 없음' or '원가·매출 줄이 아님'.
- All functions are pure: they do not change books, snap, requests or projects, and their result does not depend on
  journal or request order (sort by key/번호 internally where order matters).

## Planner decisions (D-38 details left to Claude's discretion)

- L-1 order: 수동 (프로젝트연결.csv) → 코드 → 자동 → 미연결. Manual also beats a [code] because D-38 says links must
  be fixable by a person; a wrong code in 적요 is the most likely thing to fix.
- L-2 code step: the [code] at the start of 적요 (wehago row `code`, approval.project_code) counts only when it is a key
  of `projects` (same as W-10/D-34 in 01.1). When `projects` is empty (no snapshot) any code is accepted with the label
  suffix ' (프로젝트 목록 없음)' and the auto step is skipped.
- L-3 cost auto step (Q-2 default 90 days): candidate requests have a known amount, a readable 등록일, a code that is a
  project key, norm_vendor(파트너) equal to the line's vendor_norm, and line date within [등록일, 등록일 + link_days]
  (inclusive). Amount must equal A (the line's 차변−대변) or T = A + Σ 차변 of vat_codes lines in the same
  (전표일자, 전표번호) with the same vendor_norm, T defined only when that 전표 has exactly one cost line for that vendor.
  Exactly one candidate R, and R is the single candidate of no other line → '자동 (지급요청 R)'. Several candidates →
  '미연결 (자동 연결 후보 N건: 지급요청 a, b)' (번호 sorted). R shared by several lines → each of those lines
  '미연결 (자동 연결 후보 공유: 지급요청 R)'. All request statuses take part (linking is about the project, not payment).
- L-4 revenue auto step: lines whose account_code is in revenue_codes; amount = 대변−차변; candidate projects are
  non-duplicate projects with client_norm equal to the line vendor_norm and quote (견적금액) equal to the amount;
  exactly one → '자동 (클라이언트·견적금액)'; several → '미연결 (클라이언트·견적금액 후보 N건)'; none →
  '미연결 (코드 없음 · 클라이언트·견적금액 후보 0건)' (or '미연결 (코드 <c> 프로젝트 목록에 없음 · …)').
- L-5 unknown amount (차변 and 대변 both blank): no auto step; label '미연결 (금액 미확인)' unless manual or code applies;
  summary counts it in `unknown`, never as 0.
- L-6 manual file rows: 전표일자 via util.date (any accepted format → ISO), 전표번호 stripped (a value like '22.0' saved by
  Excel becomes '22'), 줄 a positive integer, 프로젝트번호 non-blank. A bad row is ignored with
  '프로젝트연결.csv <line>번째 줄: <이유> → 무시'. Same key twice with the same project → one; with different projects →
  both ignored, '프로젝트연결.csv 같은 줄(<date> <no>-<line>)에 다른 프로젝트 지정 → 둘 다 무시'. A manual project that is
  not a key of a non-empty `projects` still applies, label '수동 (프로젝트연결.csv · 프로젝트 목록에 없는 번호)'.
