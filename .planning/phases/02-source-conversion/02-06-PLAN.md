## Interface contract

- `XCHK_FILE = "위하고대조.csv"`, `XCHK_COLUMNS = ["구분", "대상", "이름", "항목", "금액", "건수", "비고"]` — one fact
  per row; the CSV stores facts only, differences are derived by load_xchk.
- `build_xchk(books, costs, revenue, projects, requests, match, project_rows, meta, cfg, bank)` — costs / revenue:
  linking results; projects: linking.projects_of; requests: linking.requests_of (all statuses); match:
  wehago.match_requests(books, requests); project_rows: the 프로젝트.csv Table rows of plan 02-04 (dicts with
  프로젝트번호 and 계약금액 text; tests may pass literal dicts); meta: OrderedDict of 기준 facts ('장부 기준일', '분개장',
  '매입매출장', '전자세금계산서(매입)', '인트라넷 스냅숏', '변환 시각'); cfg: convert.read_config (cash_codes); bank:
  `{"balances": rows of 계좌잔액.csv or None, "transactions": rows of 입출금내역.csv or None}` (raw text dicts with the
  data.SCHEMA columns; None = file missing). Returns Table(XCHK_FILE, XCHK_COLUMNS, rows, checks, notes). No file access.
- `load_xchk(input_dir)` → `{"state": 'ok' | '자료 없음' | '읽을 수 없음', "reason", "meta", "status", "projects",
  "outside", "unlinked", "unlinked_lines", "vendors", "vendor_summary", "revenue", "revenue_unlinked",
  "revenue_unlinked_lines", "cash", "cash_months", "totals"}`; never raises.

## Planner decisions

- X-1 row kinds in order: 기준 (항목 = meta key, 비고 = value); 요청상태 (대상 = each wehago.STATUSES; 항목 '인트라넷 요청'
  금액, 건수, 비고; for 계산서 있음 / 금액 차이 a second row 항목 'WEHAGO 계산서'); 프로젝트원가 per project key (projects
  order, then keys reached only by manual links with 이름 '(프로젝트 목록에 없음)'): 'WEHAGO 원가' (lines, all dates),
  '실행가', '요청 누계' (approval._projects rule: code = key and status ≠ 'status_unknown'); 프로젝트밖요청 (대상 '합계');
  미연결원가 (대상 '합계') then 미연결원가줄 per line (대상 'YYYY-MM-DD 전표-줄', 이름 거래처, 항목 = link label, 비고 = masked
  적요); 거래처미지급 per row of wehago.vendor_payables(books, requests, match) (settled = (), 항목 'WEHAGO 미지급' and
  '인트라넷 요청') then 거래처미지급요약; 매출계약 per project ('WEHAGO 매출' — 0 when the books hold no line for it,
  '계약금액 (수동 입력)' from project_rows — blank → '' with 비고 '미등록' (D-49), '견적금액'); 매출미연결 (대상 '합계') then
  매출미연결줄; 보통예금 (D-48: '기초 잔액 (전기이월·기초잔액 줄)', 'WEHAGO 증감 (전체 기간)', 'WEHAGO 잔액 (장부 기준일)',
  '계좌잔액.csv 잔액 합계'); 보통예금월 per YYYY-MM with cash lines ('WEHAGO 증감', '입출금내역 증감 (입금−출금)').
- X-2 B5 unknown rule: a 금액 cell is '' whenever any contributing amount is unknown (request amount, cost line, bank
  row); the count of unknown contributors goes to 비고 ('금액 미확인 N건' / 'N줄'); 건수 still counts every contributor.
- X-3 보통예금 (D-48): cash lines = account_code in cfg cash_codes. Opening lines = cash lines whose 적요 contains
  '전기이월' or '기초잔액'; they form '기초 잔액' and are excluded from every 증감. No opening line → 기초 잔액 and WEHAGO
  잔액 are '' with 비고 '판단 불가 — 기초 잔액 줄 없음'. 계좌잔액 합계 = Σ 잔액 of the row with the latest 기준일 per 계좌명
  (any unknown → ''), 비고 '기준일 <dates>' and the note '계좌잔액.csv는 현금계정 밖 계좌도 담을 수 있음'. 입출금내역 증감 per
  month = Σ 금액 of 입금 − Σ 금액 of 출금 rows dated in that month.
- X-4 vendor comparison keeps the 01.1 rule exactly (wehago.vendor_payables), so the monthly numbers and the approval
  panel agree; a vendor row with requested_unknown > 0 has 인트라넷 요청 '' (X-2).
- X-5 load_xchk derives differences only from known values (None otherwise), totals of registered 계약금액 and of known
  실행가 with their blank counts, and validates the header and every non-blank 금액 / 건수 cell.
