# Phase 01.1 Plan 03: Collection run, 구조 점검 and launcher Summary

**`승인검토.py --수집 함` joins the guarded collector to the snapshot and the checkbox screen with a hidden-password prompt, scrubbed one-line failures and exit codes 0/2-7, `--구조점검` checks page 1 of each list and writes nothing, and `실행_승인검토.bat` double-clicks the whole thing; 45 new tests prove it against a fake site with no network and a credential sentinel sweep.**

## Accomplishments

- **Collection run:** `--수집 함` asks `input("인트라넷 ID: ")` and `getpass.getpass(...)` once each, takes `collected_at` just before login (P-13), prints progress and `수집 완료: 지급요청 1쪽 9건 · 프로젝트 1쪽 4건 · X.X초`, saves with `write_snapshot`, builds the screen with `collected_now=True`, opens the browser. Against the 9-request / 4-project fake site the headline reads `전부 승인 시 최저 잔액 98.2 백만원 · 2026-12-25` and the start line says `(이번 실행에서 수집)`. Requests are exactly `GET /`, `POST /login/submit`, `GET /payment/index`, `GET /project/index`.
- **Password safety:** no option, environment read or launcher variable carries credentials (tests on option names, greps for `os.environ|getenv` and `set /p`). `getpass` runs under `warnings.simplefilter('error', GetPassWarning)`; the real fallback was exercised from a piped shell and stops with exit 2 and the Korean explanation before a character is read. Every printed failure goes through `_scrub` (raw and urlencoded forms become `***`), no traceback module is used and no exception is re-raised during collection.
- **Exit codes (P-14):** 2 input problem/empty credentials/cancel/echoing console; 3 login failure or structure change; 4 blocked request; 5 network/TLS/HTTP-protocol failure inside collect; 6 any other exception or Ctrl+C; 7 disk failure after a successful collection (separate try block, so a full drive is never reported as a connection failure). A stopped run leaves root and out empty.
- **구조 점검:** `intranet.structure_report` logs in and reads page 1 of each list through the same guarded opener (4 requests). The CLI prints header match or the differing names, row counts, page-link forms, the largest page number against `--최대페이지`, the query names of same-list links it would not follow, and the counts 금액 미확인 / 등록일 해석 불가 / 프로젝트 코드 없음. It prints no row value and creates no file or folder; exit 0 when matching, 3 otherwise.
- **Launcher:** `실행_승인검토.bat` is UTF-8 without BOM, CRLF on every line, `chcp 65001` first; a test pins that it differs from `실행_주간.bat` in exactly three lines (an `echo` announcing the prompt, the run line `%PY% 승인검토.py --수집 함 %*`, the success text).
- **One source for keys:** `intranet.PAYMENT_KEYS is snapshot.PAYMENT_COLUMNS` and likewise for projects.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] `structure_report().ok` also requires no cell-count mismatch and no paging stop**
- **Found during:** Task 2 design
- **Issue:** the plan sets ok = both headers match and both lists have a row. A page-1 report could say "예상과 일치" while `collect()` would stop at once on a differing cell count or an unrecognised paging link (the stops added in plan 02), which would make the first-run check misleading.
- **Fix:** `ok` also requires `bad_rows == 0` and an empty `paging_stop` (same rule as `_collect_list`); both are shown as separate report keys and printed ("이대로면 수집이 멈춥니다"). Test `test_unknown_paging_is_not_ok`.
- **Files modified:** ceo_report/intranet.py, 승인검토.py, tests/test_approval_cli.py
- **Commit:** 708d745 (tests 7844803)

**2. [Rule 1 - Bug] Test compared a percent-encoded file URI with the plain file name**
- **Found during:** Task 1 GREEN
- **Issue:** `pathlib.Path.as_uri()` percent-encodes the Korean file name, so `target.endswith("승인검토_….html")` was false although the code was right.
- **Fix:** the assertion unquotes the URI first.
- **Files modified:** tests/test_approval_cli.py
- **Commit:** 8970ed1

**3. [Rule 3 - Blocking] Shared helpers refactored so the structure check reuses collect()'s logic**
- **Found during:** Task 2 GREEN
- **Issue:** `_find_table`, `_read_rows` and `_classify_links` raised or returned too little for a non-raising report.
- **Fix:** extracted `_match_table` and `_split_rows`, and `_classify_links` returns one more value (link-shape info); `_find_table`/`_read_rows` keep their old behaviour. All 57 plan-02 tests stay green.
- **Files modified:** ceo_report/intranet.py
- **Commit:** 708d745

**Total deviations:** 3 auto-fixed (1 missing-critical, 1 test bug, 1 blocking refactor). **Impact:** none relaxes a plan truth; the structure check is slightly stricter than specified.
