# Phase 01.1 Plan 05: WEHAGO xlsx reader and matching engine Summary

**Standard-library reader for 분개장, 매입매출장 and 전자세금계산서(매입) with an exact header check, 장부 기준일/freshness/failure states, 주민번호 masking, and the D-32/D-33/D-34 matching engine (request status, vendor 미지급금 difference, project (도) cost), all proven on synthetic workbooks written at test time.**

## Accomplishments

- `read_xlsx`: zipfile + xml.etree only; first sheet resolved through `xl/workbook.xml` and its rels (not by part name); shared strings (plain and rich), inlineStr, `t="str"`, error/boolean cells read as empty, sparse and `r`-less cells placed by column; `date1904` flag kept on the result.
- Guards (T-01.1-41): `MAX_PART_BYTES` (50 MB) checked against `ZipInfo.file_size` and again on a bounded read; any part containing `<!DOCTYPE` or `<!ENTITY` (UTF-8, UTF-16 LE/BE) is refused before parsing; column index capped at 256; nothing is extracted to disk.
- `read_book` / `load_books`: header names compared after removing all whitespace, columns found by name, the repeated `Code` of 분개장 matched by order; any missing or extra name stops that file and the whole cross-check (all three row lists emptied) with `<file> 머리글이 예상과 다름 — 없음: … · 추가: …` and a `books.header` detail. File choice: `~$` owner files skipped, 매출 e-invoice exports go to `unused`, `.xls/.csv` look-alikes are named in the `자료 없음` reason, newest file date wins. Subtotal and blank rows are skipped and counted (`skipped`), undated data rows are kept and counted (`undated`), 매출 ledger rows are counted (`sales`) but not kept.
- `match_requests`: the nine D-32 labels of the plan reproduce exactly (1201 계산서 있음 … 5109 이미 지급 (분개장 2026-10-30 전표 20)); summary 3 / 51,700,000, 금액 차이 1 (160,500,000 / 165,000,000 / +4,500,000), 계산서 없음 1 / 264,000, 이미 지급 1 / 49,500,000, 연결 불가 3 / 4,400,000 / 1 unknown; `schedule_amount` is the WEHAGO total only for 금액 차이 (D-30a).
- `vendor_payables`: 7 listed rows (6 with a difference, 차이 합계 +10,976,000, 1 판단 불가 가상숙박) out of 9 compared, `기초잔액 미반영`; a `전기이월` line removes the label and gives 가상임대 +4,000,000 and 합계 +11,976,000.
- `project_costs`: 26201 40,000,000; 26220 158,000,000; 26221 5,400,000; 26203 45,000,000; unlinked 2 lines 1,100,000; the 45100 `(도)외주비` line is in neither.
- `mask_rrn`: every 6+7-digit run (optional `-` or space, any seventh digit, also inside a longer digit run) becomes `******-*******`; `123-45-67890` stays; the 사업자(주민)번호 column is never read into a row.

## Follow-up fix (D-35c)

A read-only check of the user's real WEHAGO exports (recorded as D-35c in 01.1-CONTEXT.md) changed three reader rules. Commits: `b49b5f2` (RED tests), `8011daa` (GREEN fix). Full suite: `Ran 378 tests ... OK` (363 + 15 new, one of the 363 updated). Only synthetic workbooks were used.

- **Header rule.** A file stops (`HeaderMismatch`, `머리글 다름`) only when a required column is missing or renamed. Extra columns after or between the required ones are ignored and recorded: `read_book` info and `books.files[kind]` carry `extra_columns` (list of names) and `extra_note` (`추가 열 무시: <names>`, empty string when none). The real 매입매출장 header (14 expected columns plus Code, 계정과목, Code, 부서명, Code, 프로젝트명, Code, 카드사명) now loads. A mismatch message still lists `추가:` names when a column is also missing (a rename reads `없음: 적요 · 추가: 메모`).
- **Summary rows.** A row is skipped (counted in `skipped`, kept out of `rows`, `undated` and `last_date`) when any trimmed cell starts with 합계, 소계, 일계, 월계 or 누계 (leading brackets ignored), or contains `거래처별 소계`. This no longer requires the date cell to be empty. Fixtures use the real strings `합계 (건수 : 4,292 )`, `거래처별 소계: 9건`, `합계(거래처:166) : 753건`.
- **Book date.** The 장부 기준일 stays the file-name date. Rows dated after it are kept and counted: `info['after_ref']`, `books.files[kind]['after_ref']`, and the total `books.after_ref` (for the screen's `장부 기준일 이후 전표 N건`). Without a file-name date the count is 0. `last_date` does not move the book date. `match_requests` (`_payment_lines`) uses only journal lines dated on or before `books.book_date`.
- **Updated test.** `test_an_extra_column_alone_also_stops_everything` became `test_an_extra_column_alone_no_longer_stops`: D-35a stopped on an extra column alone, D-35c supersedes that. The missing-column and renamed-column tests are unchanged.
- **Notes for plan 01.1-06.** `books.state` is still `머리글 다름` only for missing/renamed columns, so a file with ignored extra columns is `ok`; show `extra_note` per file. `vendor_payables` and `project_costs` still use every journal line, including those after the 장부 기준일.
