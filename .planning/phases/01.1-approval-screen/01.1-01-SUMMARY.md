# Phase 01.1 Plan 01: Snapshot, 8-week engine and checkbox screen Summary

**Snapshot-on-disk to one HTML page with 8 Monday-start weeks, per-request checkboxes and a node-verified JS recompute, built by `승인검토.py` from the newest snapshot with no network, and the weekly/monthly reports proven byte-identical.**

## Accomplishments

- `snapshot.py`: three UTF-8 BOM CSVs per snapshot folder, atomic rename, refusal of a duplicate collection time, SnapshotError on a missing column or a row count that differs from 수집정보. A failed `os.rename` leaves nothing behind.
- `approval.build/scenario`: 잔액 기준일 is the schedule cutoff (P-3), events between it and the grid Monday roll onto day 0 and are counted (P-8), approved requests after the cutoff are fixed outflows, P-6 number and key matching with 'replaced', 'unmatched', '중복 제외' and '중복 가능성' counts.
- Page: sticky one-line headline (`전부 승인 시 최저 잔액 98.2 백만원 · 2026-12-25`, 최소보유현금 미만 badge with the week), 추정 입금 포함 line, start line with collection time and age, request table with `이 건 빼면·넣으면 최저 잔액`, weeks table, `div#schedule-notes`, `div#issues`.
- Settings: `승인검토_주수` (int >= 1, else 8 with an 입력 확인 line) and `승인검토_정기지출` (blank -> default list with an 입력 확인 line); defaults live in `APPROVAL_DEFAULTS`, not `DEFAULT_SETTINGS`.
