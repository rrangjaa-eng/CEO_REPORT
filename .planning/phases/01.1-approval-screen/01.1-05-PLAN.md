## Interface contract (plan 01.1-06 reads these names)

- KIND_HEADERS: ordered mapping of kind → expected header names after whitespace removal.
  - '분개장': 전표일자, 전표번호, 구분, Code, 계정과목, 차변, 대변, 거래처, Code, 적요.
  - '매입매출장': 구분, 전표일자, 번호, 거래처, 사업자(주민)번호, 품명, 공급가액, 부가세, 합계, 신고월, 전자세금, 11일이내, 매입/매출유형, 분개유형.
  - '전자세금계산서(매입)': 일자, Code, 거래처, 유형, 품명, 공급가액, 부가세, 합계, 차변계정, 대변계정, 관리, 전표상태.
- read_xlsx(path) → list of rows of the first sheet; each row is a list of cell texts ('' when empty), numeric cells as their raw value text. Raises WehagoError.
- load_books(folder, asof, stale_days) → Books with: state ('ok', '자료 없음', '경과', '머리글 다름', '읽기 실패'); reason (one Korean line, '' when ok); book_date; files (kind → name, file_date, last_date, ref_date, rows); header (on '머리글 다름': file name, missing names, extra names); unused (file names not chosen); journal, ledger, einvoice (lists of dicts, below). Never raises for missing, stale or malformed files.
  - journal rows: date, no, account_code, account, debit, credit, vendor, vendor_norm, memo, code.
  - ledger rows (구분 '매입' only; 매출 rows are counted, not kept): date, no, vendor, vendor_norm, item, code, supply, vat, total.
  - einvoice rows: date, vendor, vendor_norm, item, code, supply, vat, total, debit_account, slip_state.
  - Amounts are int or None; dates are date or None; texts went through mask_rrn.
  - When state is not 'ok', journal, ledger and einvoice are empty lists (D-35a: no partial use).
- norm_vendor(name) and mask_rrn(text) are public.
- match_requests(books, requests) → {"rows": {번호: {"status", "label", "invoice_total", "diff", "schedule_amount", "candidates", "source", "payment"}}, "summary": status → {"count", "sum", "unknown", "diff", "invoice_sum"}}. schedule_amount is the invoice total for '금액 차이' and the intranet amount otherwise (W-8). status is one of '계산서 있음', '금액 차이', '계산서 없음', '이미 지급', '연결 불가', '판단 불가'. requests are A['requests_all'] dicts (번호, vendor, amount, code, registered, status).
- vendor_payables(books, requests, match) → {"rows", "compared", "diff_count", "diff_sum", "unknown_count", "opening", "note"}, where opening is True when the 분개장 has an opening-balance line (W-13) and note is '' then, else '기초잔액 미반영'. Each row: vendor (WEHAGO name, else the intranet name), payable, requested, requested_unknown, diff (int or None).
- project_costs(books, project_keys) → {"by_code": code → {"cost", "lines"}, "unlinked": {"count", "sum", "lines": [{date, vendor, memo, amount}]}}.

## Planner assumptions (shown on the screen by plan 01.1-06)

- W-1 (D-31) file choice: a .xlsx file in the folder belongs to a kind when its name contains '분개장', '매입매출장' or '전자세금계산서'. Its file date is the first 8-digit run after '_' that parses as YYYYMMDD. With several files of one kind, the newest file date wins (then the newest modification time); the others go to unused.
- W-2 (D-31) header: row 1 of the first sheet in workbook order (resolved through xl/_rels/workbook.xml.rels, not by part name). Names are compared after removing all whitespace, so '11일\n이내' equals '11일이내'. Every expected name must be present and no other name may appear; a repeated name ('Code' in 분개장) is matched by order of appearance; columns are found by name, so order does not matter. Any missing or extra name is a header mismatch (D-35a): reading of that file stops right after row 1 and WehagoError names the file, the missing names and the extra names.
- W-3 (D-31, D-35) a file's ref date is its file date, else its last row date. book_date is the oldest ref date of the three. The books are stale when (asof − book_date).days > stale_days (위험_자료경과일, default 7).
- W-4 (D-35, D-35a) the cross-check runs only when all three kinds are present, readable, header-correct and fresh. Otherwise the whole cross-check stops: journal, ledger and einvoice are emptied (no partial or guessed values), state and reason say why, every request is '판단 불가(WEHAGO 자료 없음)', '판단 불가(WEHAGO 자료 경과)', '판단 불가(머리글 다름)' or '판단 불가(WEHAGO 읽기 실패)', and nothing is marked '이미 지급'. Precedence when several apply: 머리글 다름, 읽기 실패, 자료 없음, 경과.
- W-5 (D-32) norm_vendor: unicodedata NFKC (turns '㈜' into '(주)'), remove '(주)' and '주식회사', remove all whitespace. Project codes come from approval.project_code applied to 품명 or 적요.
- W-6 (D-32) per-request order: books not ok → 판단 불가; amount unknown → '연결 불가 (금액 미확인)'; normalised vendor in no book → '연결 불가 (거래처 후보 0건)'; payment check (W-7); request without code → '연결 불가 (프로젝트 코드 없음)'; invoices = 매입매출장 매입 rows with the same normalised vendor and code, or, only when there are none, 전자세금계산서(매입) rows by the same rule (label suffix ' (전자세금계산서)'). No invoice → '계산서 없음'. Exactly one invoice whose 합계 equals the amount → '계산서 있음'. No equal invoice and exactly one invoice → '금액 차이 (계산서 X · 차액 ±Y)', with diff = invoice 합계 − request amount. Anything else → '연결 불가 (계산서 후보 N건)'. An invoice that is the exact match of two requests makes both '연결 불가 (계산서 후보 공유)'.
- W-7 (D-32, D-35) '이미 지급': a 분개장 line whose 계정과목 (whitespace removed) is 미지급금 or 미지급비용, with 차변 equal to the amount, the same normalised vendor, 전표일자 on or after the request's 등록일 date (when known) and, when its 적요 carries a [code], the same code. Exactly one such line that no other request also matches → '이미 지급 (분개장 <date> 전표 <no>)'. More lines, or a shared line → '연결 불가 (지급 후보 N건)'. A doubtful payment therefore stays in the schedule.
- W-8 (D-30, D-30a) a '금액 차이' request is scheduled at the WEHAGO invoice 합계 (schedule_amount): the toggle amount when pending, the fixed outflow when approved. The intranet request amount and the difference are shown next to it. Every other status keeps the intranet amount ('계산서 있음' is equal by definition; the other statuses have no single WEHAGO amount). D-33 deliberately compares the intranet request amounts, because it is the intranet-versus-books comparison.
- W-9 (D-33) payable per normalised vendor = Σ대변 − Σ차변 over 미지급금 and 미지급비용 lines in the file period, opening-balance lines included. The label '기초잔액 미반영' is shown only when the 분개장 holds no opening-balance line (W-13); no 합계잔액시산표 is read in this phase. requested = requests with status pending or approved whose WEHAGO status is not '이미 지급'. Any unknown request amount makes that vendor's diff None ('판단 불가'). Rows: diff ≠ 0 or None; sorted by |diff| descending, then normalised name; 판단 불가 rows last. compared = number of vendors that appear on either side.
- W-10 (D-34) (도) cost = 분개장 lines whose 계정과목 contains '(도)' and whose account Code is five digits starting with 6. Amount = 차변 − 대변. The project comes from the 적요 [code]. No code, or a code that is not a snapshot project key → unlinked.
- W-11 (D-36) the 사업자(주민)번호 header is checked but its cells are never stored. Every kept text goes through mask_rrn. mask_rrn replaces six digits, an optional '-' or space, then seven digits (any first digit), not inside a longer digit run, with '******-*******'. Over-masking a 13-digit number is accepted; the 3-2-5 사업자번호 form never matches.
- W-13 (D-33) the 분개장 holds an opening balance when at least one 미지급금 or 미지급비용 line has an 적요 that, with whitespace removed, contains '전기이월' or '기초잔액'.
- W-12 (D-31) 전자세금계산서 일자 'MM-DD' takes the year of its file date (asof when absent), minus one when MM-DD falls after that date's month-day.
