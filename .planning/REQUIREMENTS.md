# Requirements: CEO_REPORT

**Defined:** 2026-11-02
**Core Value:** 수익·현금·예정 입출금·예산 집행을 섞지 않고, 미확인 값을 0으로 넣지 않으며, 표시 범위·전체 건수·합계를 함께 보여 준다.

## v1 Requirements

### 자금 (CASH)

- [x] **CASH-01**: 대표가 계좌별 잔액·합계·사용제한·사용 가능액을 보고 기준일 기준으로 본다
- [x] **CASH-02**: 기간 시작 잔액·실제 입금·출금·기간 말 잔액을 보고, 회사 계좌 간 이체는 회사 전체에서 빠진다
- [x] **CASH-03**: 출금이 프로젝트 지급·회사 공통지출·카드대금 등 분류별로 나뉜다

### 일정 (PLAN)

- [x] **PLAN-01**: 4주는 주별, 이후 6개월까지 월별 입금예정·지급예정·계산 잔액을 확정/추정으로 나눠 본다
- [x] **PLAN-02**: 기간 중 최저 계산 잔액과 날짜가 확정만/확정+추정 두 가지로 나온다
- [x] **PLAN-03**: 날짜 없는 예정금액과 입금예정일이 지난 미수는 그래프에 넣지 않고 별도 표로 나온다

### 프로젝트 (PROJ)

- [x] **PROJ-01**: 프로젝트마다 예산·수정일·이번 기간 지급·누적 지급·요청 미지급·카드 미결제·미요청 계획·지급률·예상 잔여예산이 나온다
- [x] **PROJ-02**: 공급가 기준 금액과 부가세 포함 실출금을 분리하고 카드는 총액으로 둔다
- [x] **PROJ-03**: 예산 미지정이면 '예산 미지정', 비율·잔여예산은 '판단 불가'이고 남은 예산을 지급예정으로 만들지 않는다
- [x] **PROJ-04**: 첫 화면은 일부만 보여도 표시 건수/전체 건수/전체 합계를 함께 보여 준다

### 손익 (PL)

- [x] **PL-01**: 당월·연누적 매출·직접비·이익·이익률, 공통비 차감 손익을 회사·팀·프로젝트로 본다
- [x] **PL-02**: WEHAGO 손익과 인트라넷 완료보고 손익을 따로 본다
- [x] **PL-03**: 계약 중 매출 미반영액과 종료 시점 예상이익을 보고, 미확인 원가가 있으면 '판단 불가'

### 수금 (AR)

- [x] **AR-01**: 계약·발행·미발행·미수·입금예정일·경과일을 프로젝트별로 본다
- [x] **AR-02**: 완료일이 있을 때만 미발행 경과일을 계산한다
- [x] **AR-03**: 선수금·취소·환불·수정 건이 따로 나온다

### 지급의무 (AP)

- [x] **AP-01**: 급여·회사 부담금·임차료·구독료·세금·카드대금·차입금·보증금·설비 지출이 분류별로 나온다
- [x] **AP-02**: 거래처별 미지급 잔액과 가장 가까운 지급일이 나오고, 프로젝트 지급과 중복되지 않는다

### 자료 범위 (DATA)

- [x] **DATA-01**: 기간 내 변경 전후(예산·계약·입금예정일·지급예정액)와 지급계획 대비 실제·계획 외 지급이 나온다
- [x] **DATA-02**: 예산 미지정·프로젝트 미연결·지급일 미등록 금액, 자료 기준일, 원천자료 간 차이가 나온다
- [x] **DATA-03**: 요약과 상세 합계를 대조한 결과와 입력 오류 목록이 보고서에 실린다

### 보고서 (REP)

- [x] **REP-01**: 주간·월간 보고를 명령 한 줄(또는 실행.bat)로 만든다
- [x] **REP-02**: 대표용과 경영관리용의 숫자가 같고, 대표용에는 위험·권고 문구가 없다
- [x] **REP-03**: HTML과 PDF(Edge/Chrome 있으면)가 출력 폴더에 저장된다

### 지급 승인 검토 (APPR) — Phase 01.1

- [ ] **APPR-01**: 승인 대기 요청을 체크박스로 넣고 빼면 1초 안에 8주 주별 잔액·최저 잔액(날짜)·부족 주가 다시 계산된다
- [x] **APPR-02**: 요청마다 '이 건을 빼면 최저 잔액'과 예상 지급일(근거 규칙)이 보인다
- [x] **APPR-03**: 첫 줄에 전부 승인 시 최저 잔액·날짜와 부족 주(0원 미만 / 최소보유현금 미만)가 보인다
- [ ] **APPR-04**: 날짜·금액·상태 미확인, 지급요청일 없음, 프로젝트 미연결, 미요청 실행가, 미등록 정기 지출이 0으로 합산되지 않고 건수·금액으로 보인다
- [x] **APPR-05**: 승인 완료·지급 전 요청, 자금일정, 입금예정이 일정에 들어가고 같은 지급이 두 번 들어가지 않는다. 주간·월간 보고서 결과는 바뀌지 않는다
- [x] **APPR-06**: 실행_승인검토.bat 더블클릭 → ID·비밀번호 입력 → 수집 → 화면이 열린다. 수집 없이 마지막 스냅숏으로도 만들고 수집 시각이 보인다

### 인트라넷 수집 (CRAWL) — Phase 01.1

- [x] **CRAWL-01**: 허용 경로만 요청하고 /confirm·/logout·삭제·다른 호스트·http·리디렉션 대상은 요청 전에 막는다(테스트로 증명)
- [x] **CRAWL-02**: ID·비밀번호는 실행 때 입력받아 메모리에만 두고 어떤 파일·로그·출력에도 남지 않는다
- [x] **CRAWL-03**: 지급요청·프로젝트 목록 전 페이지를 수집 시각이 있는 CSV 스냅숏으로 저장하고, 화면 구조가 다르면 멈추고 차이를 알린다
- [x] **CRAWL-04**: 실제 수집 자료는 git에 올라가지 않는다

### WEHAGO 기준 대조 (XCHK) — Phase 01.1

- [ ] **XCHK-01**: WEHAGO 분개장·매입매출장·전자세금계산서(매입) 엑셀을 읽고, 머리글이 다르면 멈추고 차이를 알린다. 장부 기준일이 보인다
- [ ] **XCHK-02**: 승인 화면 요청마다 WEHAGO 대조 상태(계산서 있음/금액 차이/계산서 없음/이미 지급/연결 불가)와 첫 화면 상태별 건수·금액. '이미 지급'은 일정에서 빠진다
- [ ] **XCHK-03**: 거래처별 WEHAGO 미지급금 vs 인트라넷 요청 합계, 프로젝트별 WEHAGO (도) 원가 vs 인트라넷 실행가·요청 누계, 프로젝트 미연결 원가가 보인다
- [ ] **XCHK-04**: WEHAGO 실제 자료는 git에 올라가지 않고 주민번호 형태 값은 출력에 나오지 않는다

### 원천자료 (SRC)

- [ ] **SRC-01**: WEHAGO에서 내려받은 엑셀을 손익·계산서·채권채무 입력 CSV로 바꾸고, 월간 보고에 WEHAGO 기준 대조(XCHK와 같은 규칙)를 싣는다
- [ ] **SRC-02**: 인트라넷 수집 스냅숏(Phase 01.1)을 프로젝트·집행 입력 CSV로 바꾼다

### 배포 (DEP)

- [ ] **DEP-01**: 프로그램과 결과물이 F:\CLAUDE\CEO_REPORT에 있고 거기서 실행된다
- [ ] **DEP-02**: 결과물이 Google Drive로 옮겨진다
- [ ] **DEP-03**: 코드가 GitHub CEO_REPORT 저장소에 있다
