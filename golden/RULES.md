# 정답 예시 규칙 표

지금 프로그램이 지키는 규칙과, 그 규칙을 보여 주는 사례(golden/cases/<사례>)입니다. 새 시스템은 모든 사례에서 기대값과 1원까지 같아야 합니다.
'의심'에 적힌 것은 지금 프로그램의 결과가 틀렸을 수 있어 사용자 확인이 필요한 항목입니다.

## D. 자료 규칙 (실제 자료에서 배운 것)

| 번호 | 규칙 | 사례 | 기대값에서 볼 곳 | 의심 |
|---|---|---|---|---|
| D1 | 한 계산서를 여러 프로젝트로 나누면 공급가 비례로 줄을 나누고, 자금계획과 맞출 때 다시 합침 | | | |
| D2 | 같은 이름이라도 거래처코드가 다르면 다른 거래처(경고), 다른 지급 | | | |
| D3 | 거래처코드 앞자리 0은 무시([000101] = 00101) | | | |
| D4 | 옛 프로젝트 번호(5자리 미만)와 2025년 이전 해는 전년 프로젝트 | | | |
| D5 | 옛 인트라넷 프로젝트(2026-03-31까지)는 완료로 봄 | | | |
| D6 | 분개장 중복 줄(sq_acttax2 같음)은 한 번만 | | | |
| D7 | 받다 만·깨진 확장 분개장 JSON은 쓰지 않음 | | | |
| D8 | 새 회계연도에 전기이월이 없으면 은행 잔액은 계좌잔액으로 | | | |
| D9 | 결산 분개는 손익에서 빼되 감가상각은 남김 | | | |
| D10 | 선수금 계산서는 적요가 아니라 계정 25900으로 판단 | | | |
| D11 | 카드 거래처 이름 '카드사_1234' 형식 | | | |
| D12 | 만기일이 빈 계산서는 발행일 + 60일 | | | |
| D13 | 계좌잔액에 손으로 넣은 정기예금 줄이 장부보다 우선 | | | |
| D14 | 수동 연결 파일도 거래처코드·금액으로 다시 확인 | | | |
| D15 | 옛 인트라넷 프로젝트의 '장부 원가 0원' 오탐 없음(올해 장부에 이어진 원가 포함) | | | |
| D16 | 프로젝트 연결 순서: 수동 연결 → 매입매출장 프로젝트 칸 → 적요 [코드] → 유일한 자동 후보 → 미연결 | | | |

|---|---|---|---|---|
| F1 | 대체(재분류) 전표는 지급이 아님 | | | |
| F2 | 100원 끝전 차이는 같은 금액으로 맞춤 | | | |
| F3 | '이미 지급' 확인 창: 계획일 31일 전 ~ 15일 뒤 | | | |
| F4 | 전표 하나는 계획 하나에만 씀 | | | |

| F7 | 기준일보다 7일 넘게 묵은 자금계획은 쓰지 않음 | | | |
| F8 | 자금계획은 방향·금액·거래처코드가 같은 기존 일정을 대신함 | | | |
| F9 | 인트라넷 지급요청·남은 예산은 기본으로 자금 일정에서 뺌 | | | |

| F13 | 꼭 나갈 정기 지출(급여·4대보험·카드)은 '예상'이어도 여유 자금에서 뺌 | | | |
| F14 | 세금 예상(세금예상.csv)을 일정에 합침, 없으면 막음 | | | |
| F15 | 날짜 지난 미입금 계산서는 출금일로 옮긴 사본으로 일정에 둠 | | | |

## U. 사용자가 정한 규칙

| 번호 | 규칙 | 사례 | 기대값에서 볼 곳 | 의심 |
|---|---|---|---|---|
| U1 | 모르는 값은 0으로 넣지 않고 '확인된 합계 + 미확인 N건' | | | |
| U2 | 자금계획서가 없으면 대표 보고를 만들지 않음 | | | |

| U4 | 장부 잔액이 있으면 장부가 이기고 계좌잔액은 제한(담보 등)에만 | | | |
| U5 | 계좌 사이 이체는 입출금에서 뺌 | | | |
| U6 | 카드 대금은 이중으로 세지 않음 | | | |
| U7 | 날짜 없는 금액은 따로 표로 | | | |
| U8 | 해 바뀜(12/31~1/2 기준일)에도 전년·올해 금액이 두 번 세지지 않음 | | | |
| U9 | 주민번호는 결과 어디에도 그대로 나오지 않음 | | | |
| U10 | 분개장·자금계획서가 다른 회사 자료면 막음 | | | |
